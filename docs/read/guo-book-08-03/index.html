信号引擎、订单状态与性能

将预测转换为订单状态机，并用尾部延迟、内存访问和浮点误差检查实现。

预测下一分钟收益，并不直接产生一笔可以发送的订单。程序还需要知道当前持仓、挂单、行情是否有效，以及风险限额是否允许继续交易。信号引擎把这些状态与预测结合，订单管理模块再负责执行和记账。

信号引擎处理什么

设预测收益为 r^\hat rr^，预期成本为 ccc。一个简化规则是在 r^>c\hat r>cr^>c 时增加仓位，在 r^<−c\hat r<-cr^<−c 时减少仓位。真实指令还取决于已有挂单：若目标买入 100 股，已经有 80 股未成交买单，则新增需求最多为 20 股，而不是再发 100 股。

触发器可以来自行情，也可以来自成交、拒单、计时器和风险状态变化。为确保相同输入得到相同决策，应保存事件顺序、模型参数版本和初始状态。研究原型与线上实现共享核心计算，或用同一组输入逐项比对输出，可以减少模型移植时的差异。

从预测收益推到目标仓位

设 www 是分配给一只股票的资产比例，r^\hat rr^ 是下一期预测收益率，σ2\sigma^2σ2 是同一期收益方差，γ>0\gamma>0γ>0 表示风险惩罚强度。暂不计交易成本时，一个简单目标为

max⁡w{wr^−γ2w2σ2}.\max_w\left\{w\hat r-\frac\gamma2w^2\sigma^2\right\}.wmax​{wr^−2γ​w2σ2}.

对 www 求导得到 r^−γwσ2=0\hat r-\gamma w\sigma^2=0r^−γwσ2=0，故未加约束的目标为 w∗=r^/(γσ2)w^*=\hat r/(\gamma\sigma^2)w∗=r^/(γσ2)。再用持仓上下限截断，最后按账户净值和价格换算股数。例如净值 100 万元、目标比例 2%、价格 50 元，对应 400 股。已有 200 股，另有 150 股买单仍可能成交，新增需求为 400−200−150=50400-200-150=50400−200−150=50 股。

若买入最小申报单位要求按 100 股处理，50 股需求不能直接发出。系统应按该证券的交易规则取整或等待需求累计。这里的收益、方差与成本必须属于同一预测周期。把年化波动率直接与一分钟收益预测代入同一个目标，会改变风险惩罚的实际尺度。

用状态机管理一张订单

订单至少区分待确认、已接受、部分成交、撤单待确认、已撤销、已成交和已拒绝。假设买单数量 100：接受后成交 40，随后请求撤单，在撤单确认前又成交 20，最后撤销剩余 40。最终持仓增加 60，撤销量为 40，二者之和仍为原订单 100。

成交回报需要唯一执行编号。重复收到同一编号时不能重复加仓；“累计成交量”字段与“本次成交量”字段也不能相加混用。替换订单还需保存原订单与新订单的关联，明确它是否保留排队优先级。

订单限定条件

限价决定最差可接受价格，有效期决定等待多久。日订单、GTC、立即成交剩余撤销（IOC）和全部立即成交否则撤销（FOK）对剩余数量的处理不同。中点挂钩订单随参考买卖价中点更新。冰山订单只展示总量的一部分，补充展示后的优先级取决于具体撮合规则。

Post-only 的具体行为也需要读交易场所定义。它可能在会立即主动成交时被拒绝或改价，某些实现允许在价格改善足以覆盖经济代价时成交，不能单凭名称推断一定获得被动返佣。Nasdaq 的订单说明给出了后一类例子。

平均延迟会隐藏什么

设端到端延迟为 L=Ldecode+Lmodel+Lrisk+LsendL=L_{\rm decode}+L_{\rm model}+L_{\rm risk}+L_{\rm send}L=Ldecode​+Lmodel​+Lrisk​+Lsend​。除平均值以外，还应报告第 50、99 和 99.9 百分位。例如 99% 的事件用时 5 微秒，1% 用时 100 微秒，平均只有 5.95 微秒。但每 100 次平均仍有一次进入 100 微秒的慢路径。

对需要及时撤销报价的策略，尾部延迟可能比平均值更关键。

内存访问常是慢路径之一。按行连续存储的二维数组，先遍历行内元素通常比跨行跳跃更容易利用缓存。连续存储可用一维数组下标 in+ji n+jin+j 实现。一个逐行单独分配的 T** 并不保证所有行在内存中相邻。基准测试需要防止编译器删掉计算，区分热缓存和冷缓存，并记录数据类型、数组大小、编译选项和重复次数。

SIMD 把同一种运算施加于多个数据，适合规则的连续数组。并行线程则可能增加同步和排队。静态分派有时能减少间接调用并帮助内联，但性能差异应由实际关键路径测量。不能只根据语言名称或 CPU 主频估计整套系统速度。

配套 Python 脚本还会生成 matrix_benchmark.cpp，其中用连续数组比较两种遍历次序，输出每次的耗时并检查求和结果。相邻说明文件给出编译和运行方法。可分别改变数组大小和数据类型，观察工作集超出缓存之后的差异。测试中的大缓冲区遍历用于增加缓存压力，并不保证每一级缓存都已清空。

缓存、向量化与函数分派

CPU 通常一次把相邻的一小块数据装入缓存。以 64 字节缓存行为例，连续存放的 8 字节数可以一次带入 8 个。顺序访问时后续元素可能已经在缓存中。跨很大的步长读取，每次只用一小部分已加载数据，就会增加等待内存的时间。空间局部性指相邻数据被接连使用，时间局部性指同一数据很快再次使用。

SIMD 的前提是多个元素执行相同操作。例如四只股票都更新 zi=axi+bz_i=a x_i+bzi​=axi​+b，可以成组处理。各自要走不同分支时，收益会减少。动态分派则先根据对象的运行时类型选择函数，静态分派在编译时确定调用。前者便于替换模型，后者可能帮助内联。性能设计应针对延迟占比最大的环节，而不是将所有代码改写成同一种风格。

研究原型与交易实现可以共享一个核心函数：输入特征和参数，输出预测及目标仓位。为这一个函数保存若干组固定输入和预期输出，再比较 Python 与编译语言版本，能够把“模型相同”落实到数值，而不只核对公式名称。

浮点数与订单价格

十进制 0.1 不能用有限二进制小数精确表示，因此 0.1 + 0.2 == 0.3 可能为假。对固定最小价格单位，订单价格可用整数刻度保存：价格 12.34 元、刻度 0.01 元，对应整数 1234。金额、数量相乘时仍需选择足够宽的整数类型并检查上限。

基数为 β\betaβ、有效数字位数为 ppp 的正常浮点数，在就近舍入且没有上溢或下溢时满足

鲨鱼说

“计算保留了很多位”与“结果准确”是两件事。两个已经四舍五入的价格即使用更多位相减，也无法找回被舍去的差值。先看输入精度和计算公式，再看输出的小数位。
