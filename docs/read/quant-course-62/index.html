62 · 操作风险、策略风险与监控

计算在途订单的最坏持仓，结合数值监控、压力情景与尾部损失控制风险。

操作风险来自程序、数据和流程异常，策略风险来自模型关系与市场环境变化。监控需要将异常类型对应到具体状态、限额和处理动作。

预测正确也可能因系统错误亏损

计划买100股，程序把100手误作同一字段，风险会扩大许多倍。模型已经发单，网络超时后又重试，也可能产生双倍订单。操作风险来自软件、数据、传输和人员流程，策略风险来自模型误差、市场变化与持仓暴露。两类风险会互相放大，例如过期行情既是接入故障，也使预测失去意义。

风险控制首先把危险状态变成可计算的量，再规定相应动作。净值止损只处理已发生损失，无法替代数量单位、数据完整性和未成交订单检查。

在途订单不能相互乐观抵消

当前持仓200股，未成交买单100股，新买单100股。全部买单成交后可能达到400股，若上限300，应拒绝新增。还存在未成交卖单时，也不能假设卖单必然先成交再抵消买单。

对单资产分别计算 Qmax=Q+Bpending+BnewQ_{max}=Q+B_{pending}+B_{new}Qmax​=Q+Bpending​+Bnew​ 和 Qmin=Q−Spending−SnewQ_{min}=Q-S_{pending}-S_{new}Qmin​=Q−Spending​−Snew​，检查两端。这里卖单若涉及可售数量、借券或保证金，还须核对对应状态。金额上限则用数量乘压力价格，避免数量相同但价格暴涨时名义敞口失控。

图中当前量200看似安全，加入在途和新增后的400才超过300限制。风险检查应覆盖可能的成交结果，而非只检查当前账面。

Python11 行
def check_buy(current,pending,new,price,max_quantity,max_notional):
    if any(x<0 for x in (pending,new)) or price<=0:
        return False,'字段不合法'
    worst=current+pending+new
    if worst>max_quantity:return False,'数量超过上限'
    if worst*price>max_notional:return False,'金额超过上限'
    return True,'通过'
assert check_buy(200,100,100,10,300,10000)[0] is False
assert check_buy(100,50,50,10,300,10000)[0] is True
print(check_buy(200,100,100,10,300,10000))
print(check_buy(100,50,50,10,300,10000))

第一个调用返回“数量超过上限”，第二个通过。函数仅覆盖单资产多头买入，便于读清检查顺序；扩展到多空时应分别计算最大与最小持仓。新订单量、单价和限额字段还需拒绝NaN、无穷值及错误单位。

从股数换算到风险因子

两股票各100万元，若都高度依赖同一行业，数量分散并不代表风险分散。可计算金额、行业占比、市场Beta暴露。假设A名义金额100万、Beta1.2，B空头50万、Beta0.8，则市场Beta金额为 100×1.2−50×0.8=80100\times1.2-50\times0.8=80100×1.2−50×0.8=80 万。

期权用Delta、Gamma、Vega等敏感度，债券用价格对收益率变化的敏感度。计算前应统一合约乘数和报价单位。100份Delta0.6、乘数100的期权，Delta等效股数为6000。误当作60股会低估100倍。

监控从消息到结果逐层定位

层次 观测量 异常后先处理什么
数据 行情年龄、序号缺口、非法报价 停用受影响状态并恢复数据
数值 非有限值、矩阵条件数、参数边界 停止使用失真的模型输出
订单 速率、拒单、重复意图、待确认量 阻止新异常请求并查询状态
账户 本地与外部持仓、现金差异 追溯差异成交和费用
策略 换手、滑点、预测误差、集中亏损 区分成本变化和信号失效

消息缓冲区流入快于处理速度会积压甚至丢包。盘口仍保持一组看似正常数字，不代表数据新鲜。应单独记录最后有效更新时间。模型在线求逆时，矩阵接近奇异会放大细小输入误差，条件数和输出范围能比最终损益更早暴露问题。

停机是状态转换过程

停止新增订单后，仍可能有活跃单、在途单和未确认成交。通常需要依次停止产生新风险、发送撤单、查询未明状态、处理晚到成交、对账，再决定是否平仓或对冲。直接关闭进程可能让已有挂单继续留在市场中。

软件发布还要核对全部运行节点的版本和配置。历史自动交易事故说明，部分节点遗留旧逻辑、重用旧标志或撤单机制失效，都可能迅速形成异常订单流。教学中的历史案例用于理解失效机制，不把某次事故归结为一个万能解释。

压力测试把损失分解到机制

自拟基线毛收益12%、成本3%、净收益9%。延迟一周期后毛收益7%、成本4%、净收益3%，下降6个百分点：其中5点来自毛收益衰减，1点来自费用增加。只说“手续费太高”会遗漏主要变化。

其他情景包括深度减半、价差扩大、相关性上升、某资产停牌、成交延迟和数据中断。固定信号只改一个参数可识别单项影响。联合情景则检查多种压力叠加。对于无可靠概率的异常状态，直接报告情景损失比强行赋予精确发生概率更清楚。

VaR与ES的样本含义

将损失从小到大排列，VaR是给定置信水平的分位数，ES刻画最差尾部的平均损失。自拟20个等概率情景，前18个损失不超过2万元，第19个5万元、第20个12万元。采用经验分位数定义，90% VaR为第18个值2万元。最差10%的ES为 (5+12)/2=8.5(5+12)/2=8.5(5+12)/2=8.5 万元。

当分位点有大量相同值时，不能简单把“所有大于等于VaR”的损失都平均，因为尾部概率可能超过10%；需按目标尾部质量加权。样本外未出现过的状态也不会被历史分位数自动覆盖，因此还需情景分析。

检查的证据应能定位原因

保留触发时输入、阈值、订单号和处理结果。单元检查验证现金公式或数量边界，事件回放检查整个订单链路，协议一致性检查核对接入行为，版本回归检查确认修复没有改变既有正确结果。这里的通过标准是可观察的业务状态，而不是只确认程序没有报错。

练习

1. 当前多头100，待买80、待卖70，新买50，上下持仓边界是多少？

查看解答

最大为230，最小为30。不能把全部待买卖相减后只检查160，因为成交顺序和是否成交并不确定。

2. 本地现金与外部账单相同，持仓却差10股，是否可以继续新增交易？

查看解答

应先定位未明成交、转入转出、公司行动或更正事件。现金一致不能证明股票账正确，继续新增会使差异难以追溯；在状态确认前限制新增敞口。
