66 · 学习资料索引与职业准备

按数学、市场、数据、模型和执行方向安排学习，并梳理求职项目。

后续学习可按市场、数学、数据、模型与执行五个方向展开。选择资料时，将当前问题对应到所需概念和计算方法，并通过小型项目检验理解程度。

按研究问题定位资料

量化学习涉及数学、市场、数据、模型和执行。三份资料承担不同任务：Roadmap提供主题和资源的联系，《量化交易：算法、分析、数据、模型和优化》展开统计、组合、高频及执行模型，《深入浅出Python量化交易实战》提供数据处理、策略、因子、机器学习和文本实现的补充。

使用资料时先写出当前问题。例如“均线回测为什么在换数据后失效”需要信息时间、成交假设和样本验证。“怎样提高模型复杂度”则是后续问题。资源索引的作用是把具体困难连接到必要知识，页数和工具数量不能代替掌握程度。

三条路线共享哪些基础

日频选股先完成信息时间、统计、回测、因子与组合，再开展策略研究项目。执行与做市还需要条件概率、马尔可夫过程、点过程、订单簿和动态优化。衍生品方向从现金流贴现和概率开始，继续支付复制、随机微积分、PDE、Monte Carlo与波动率。

图中的箭头表示前置依赖，不表示每个人必须用同样时间学习。能够运行随机森林，却不能解释时间切分，应先补验证。会写Hawkes公式，却不会从事件日志计算等待，应先补时间与数据。已经具备的基础可通过小练习确认后跳过。

识别“会用”与“理解”的差别

对一个方法保留四类证据：能定义变量和单位；能手算小例；能独立运行并修改程序；能解释一个失效情形。例如协整学习需要区分水平相关与平稳线性组合，亲自形成价差，说明估计样本，以及参数漂移怎样影响交易。

再以均值标准误为例：100个独立收益观测，标准差2%，均值标准误为0.2%。增加到400个相同分布独立观测，标准误降至0.1%，收益本身波动仍2%。若观测有正自相关，这个缩放会过于乐观，需要长期协方差。能解释最后一句，才说明没有只记住 s/ns/\sqrt ns/n​。

鲨鱼说

协方差，即两个变量偏离各自均值时，共同变化程度的度量。

用依赖关系安排一个小计划

假设已经掌握Python和概率，想完成一个订单执行项目，尚需事件数据2小时、队列3小时、执行优化3小时、回放项目4小时。它们有先后关系，总计12小时。每周8小时不能把四项都宣称完成，应先安排前置的8小时，再把4小时回放留给下一周。小时数是自拟计划估计，完成标准是产生相应结果。

Python18 行
dependencies = {
    "事件数据": ["Python"], "队列": ["概率", "事件数据"],
    "执行优化": ["队列"], "回放项目": ["执行优化", "事件数据"]}
hours = {"事件数据": 2, "队列": 3, "执行优化": 3, "回放项目": 4}
known = {"Python", "概率"}
plan, visited = [], set(known)
def visit(topic):
    if topic in visited:
        return
    for prerequisite in dependencies.get(topic, []):
        visit(prerequisite)
    visited.add(topic)
    plan.append(topic)
visit("回放项目")
print(" → ".join(plan))
print("估计小时", sum(hours[t] for t in plan))
assert plan == ["事件数据", "队列", "执行优化", "回放项目"]
assert sum(hours[t] for t in plan) == 12

代码按依赖关系得到“事件数据→队列→执行优化→回放项目”，总估计12小时。它先访问前置节点，使用集合避免重复加入同一项。新增一个方向共享概率基础时，不会再把已掌握内容重复计时。真实学习中根据练习错误更新估计，而非因为计划表排满就视为掌握。

把外部资源转成可验证的学习任务

教材负责定义、假设和推导，视频帮助形成整体图景，论文回答具体尚未解决的问题，代码负责复现输入与输出。阅读一个代码库时，先确认数据字段、可获得时间、费用和目标变量，再运行已知输出的小例。读懂依赖版本与运行方式后，再修改一个参数观察变化。

旧平台接口可以改写为当前本地数据实验，但要保留原问题与算法含义。不能为了让程序运行而悄悄删除退市数据、改用未来复权值，或把限价订单全部设为成交。与其追踪工具新旧，更应记录每次实现改变了哪个模型假设。

项目如何形成研究证据

一个可展示项目包括问题、数据字典、时间切分、基准、代码、结果和失败分析。日频项目可交逐期持仓与成本。因子项目交排序组合和回归误差。执行项目交订单事件与实现缺口。系统项目交重复回报、断线恢复和账户对账的记录。

结果不理想仍能说明研究能力：例如参数在训练期表现好、后期失败，定位到成本或信号衰减，再给出固定规则下的检验。简历应写自己实际完成的工作与可复现结果，不把参与阅读扩写成独立建立交易系统。

笔试与面试的表达顺序

研究题先说明条件和目标，再定义变量、给推导或算法，最后做边界与数值检查。概率题要写清独立与条件事件；回测题要画信息时间；编程题要说明输入规模、时间空间复杂度与异常输入。

例如求滚动均值，逐窗口重新相加需要约 O(nk)O(nk)O(nk) 工作量；维护窗口总和，每步加新值减旧值可降为 O(n)O(n)O(n)，但需考虑缺失值、窗口不足和浮点误差。能从算法式子落实到这些条件，比只背复杂度名称更便于判断实现是否可靠。

量化研究、开发、执行岗位各自强调模型、系统或市场机制，实际要求应读取具体职位说明。本站笔面试模块可用于逐题训练，答案先折叠，写完自己的假设与解法再展开对照，记录错误发生在哪一步。

练习

1. 模型已经能运行，但训练测试随机拆分后表现极好，首先补哪项知识？

查看解答

先补信息时间、标签重叠、按时间验证与多次试验记录。固定模型比较随机拆分和时序拆分，检查特征是否使用未来信息，再决定是否增加模型复杂度。

2. 准备汇报“策略收益20%”，还应提供哪些最少信息？

查看解答

样本起止、数据和股票池、规则是否事先固定、成本和成交时序、同期基准、波动/回撤、样本外表现，以及复算代码。没有这些条件，20%无法作为可比较的研究结果。
