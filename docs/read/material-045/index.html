1. 固定边数随机图顶点度

题目

从 n≥2n\ge2n≥2 个顶点的完全无向简单图中，等概率选择恰好 mmm 条边，0≤m≤M=(n2)0\le m\le M=\binom n20≤m≤M=(2n​)。固定一个顶点，求它的度 DDD 的分布和期望。

考点：超几何分布；指示变量；固定边数。

查看分析与解答

必要知识

无向简单图中，两顶点之间至多一条边，且没有顶点连接自身的边。顶点的度是与它相连的边数。固定总边数意味着抽中一条边后，其他边的入选机会会变化，应采用无放回抽样模型。

分析思路

把全部候选边分成“连接指定顶点”和“不连接”两类，计算抽中 k 条第一类边的方案数。期望再用指示变量求一次，避免直接求复杂组合数之和。

解答步骤

M=n(n−1)/2 是候选边总数。与指定顶点相连的有 n−1 条，其他有 M−n+1 条。k 的可行范围为 max(0,m−M+n−1) 至 min(m,n−1)，两个下界分别来自度非负和剩余边足够。

度数是“抽到的边中有几条与该顶点相连”。总候选边有 MMM 条，其中成功类有 n−1n-1n−1 条，非成功类有 M−(n−1)M-(n-1)M−(n−1) 条。要使度恰为 kkk，应从成功类选 kkk 条，再从非成功类选 m−km-km−k 条，最后除以所有选边方案数。

也可把度写成 n−1n-1n−1 个潜在邻边的指示变量之和。每条边被选中的概率都是 m/Mm/Mm/M，即使各边选择不独立，期望仍可逐项相加。

因此 P(D=k)=(n−1k)(M−n+1m−k)/(Mm)P(D=k)=\binom{n-1}k\binom{M-n+1}{m-k}/\binom MmP(D=k)=(kn−1​)(m−kM−n+1​)/(mM​)，不可行组合数记为零；ED=(n−1)m/M=2m/nE D=(n-1)m/M=2m/nED=(n−1)m/M=2m/n。

以 n=4、m=2 为例，总共六条候选边，两类各三条。D=0、1、2 的方案数分别为3、9、3，总方案数15，概率为0.2、0.6、0.2。因此均值0×0.2+1×0.6+2×0.2=1，恰等于2m/n。所有顶点度数之和为2m，也给出相同检查。

同类问题

先辨别随机图是固定边数，还是每条边独立出现。前者给超几何度分布，后者给二项分布；它们即使平均边数相同，联合概率也不相同。

2. 随机图三角形数量

题目

在 nnn 个顶点、恰好 mmm 条边的均匀随机无向简单图中，求三角形总数的期望。各边从完全图的 M=(n2)M=\binom n2M=(2n​) 条候选边中无放回选取。

考点：子图计数；联合入选概率；期望线性。

查看分析与解答

必要知识

三角形由三个顶点和连接它们的三条边组成。计数时可让每组三顶点贡献一个零一变量，随后把这些变量相加。期望可相加不要求这些三角形彼此独立。

分析思路

先固定一组三顶点，求三条边同时出现的概率，再乘三顶点集合数量。固定边数下使用条件概率连乘，不能把单边概率直接立方。

解答步骤

三条指定边依次入选的概率为 m/M、(m−1)/(M−1)、(m−2)/(M−2)。第一条入选后，可分配的入选名额和候选边都减少一，这正是后两项分母、分子变化的原因。

对每个三顶点集合 SSS 定义 ISI_SIS​：其三条边都出现时为 1，否则为 0。三角形数 T=∑SIST=\sum_S I_ST=∑S​IS​，所以只需求一组三条指定边全部入选的概率。

m≥3m\ge3m≥3 时，该概率也可写成 (M−3m−3)/(Mm)\binom{M-3}{m-3}/\binom Mm(m−3M−3​)/(mM​)，即先固定三条边，再选其余 m−3m-3m−3 条。约分后得到下降阶乘比。不同三角形可以共享边，但计算期望不需要它们独立。

记 (a)3=a(a−1)(a−2)(a)_3=a(a-1)(a-2)(a)3​=a(a−1)(a−2)，则 ET=(n3)(m)3/(M)3ET=\binom n3(m)_3/(M)_3ET=(3n​)(m)3​/(M)3​；m<3m<3m<3 或 n<3n<3n<3 时为零。固定总边数的无放回抽样不能用 (m/M)3(m/M)^3(m/M)3 代替三条边的联合入选概率。

n=4、m=3 时 M=6。任意三顶点构成三角形的概率为(3/6)(2/5)(1/4)=1/20；共有四组三顶点，所以期望1/5。期望是多次生成图后数量的平均值，可以小于一，不表示某张图包含五分之一个三角形。m=M 时公式回到完全图中的 C(n,3) 个三角形。

同类问题

数边、三角形或更复杂固定子图，都可先定义局部指示变量。若要求方差，还需按两个子图共享多少条边分类，期望中的简化不能原样用于方差。

3. 游走到零的概率

题目

随机游走从整数 49 出发，每一步独立以相同概率加 1 或减 1，到达 0 或 100 时停止。求先到达 0 的概率。

考点：首次到达；第一步分析；线性边值问题。

查看分析与解答

必要知识

先到某端点是一个终止事件，其概率取决于当前位置。h_i 表示从 i 出发先到零的概率，不是某一步位于零的概率。边界值已经由停止规则确定。

分析思路

按第一步向左、向右拆开 h_i，得到相邻状态关系。把二阶差分写成一阶差恒定，再用两个端点求直线。

解答步骤

从 i 出发，第一步后只可能在 i−1 或 i+1，且未来不再依赖此前路径，所以可用对应的 h 值继续计算。移项后的等差关系意味着每向右一格，成功概率减少相同数量。

令 hih_ihi​ 为从位置 iii 先到 0 的概率。边界为 h0=1h_0=1h0​=1、h100=0h_{100}=0h100​=0。对内部状态按第一步分类： hi=12hi−1+12hi+1.h_i=\frac12h_{i-1}+\frac12h_{i+1}.hi​=21​hi−1​+21​hi+1​. 移项得 hi+1−hi=hi−hi−1h_{i+1}-h_i=h_i-h_{i-1}hi+1​−hi​=hi​−hi−1​，说明相邻差恒定，故 hi=a+bih_i=a+bihi​=a+bi。代入边界得 hi=1−i/100h_i=1-i/100hi​=1−i/100，于是 h49=51/100h_{49}=51/100h49​=51/100。

直观上，越靠近 0 越容易先到 0；起点 50 时概率为 1/2，也与公式一致。有限区间内游走最终会吸收，所以两端命中概率相加为 1。

从零到一百共一百个间隔，概率总共下降一，所以每格下降0.01。从49出发为1−0.49=0.51。还可检查停止位置的均值：0×0.51+100×0.49=49，与公平游走起点一致。使用这个均值校验时，停止在有限有界区间是关键。

同类问题

边界命中题先写第一步关系和边界条件。若左右概率不同，一阶差不再恒定而按固定比例变化，解会转成几何形式。

4. 偏置游走有限停止

题目

在整数区间 [0,100][0,100][0,100] 内，从任意内部点开始，每步独立向左的概率为 p∈(1/2,1]p\in(1/2,1]p∈(1/2,1]，向右概率为 1−p1-p1−p，到端点停止。证明停止时间 TTT 几乎必然有限，并给出一个有限的期望上界。

考点：几乎必然终止；几何尾界；尾和公式。

查看分析与解答

必要知识

“几乎必然有限”表示无限运行的概率为零，并不表示所有路径在某个固定步数内结束。证明有限期望还要控制长时间未停止的概率，单说每次有机会结束并不充分。

分析思路

寻找对所有内部起点都有效的短期结束事件，用它把每块时间的存活概率压到同一个小于一的数，再对尾概率求和。

解答步骤

可在停止后继续假想生成左右抛掷。未来100次全向左的概率为 p¹⁰⁰；无论当前在哪个内部点，这个事件都迫使游走在100步以内碰到零。因此每一块在给定过去后仍有至少 p¹⁰⁰ 的结束概率。

“平均向左”本身并不是终止证明。需要找到从每个未停止状态出发、在固定步数内结束的统一正概率。任意内部位置距离 0 不超过 99，若随后连续 100 次都选择向左，一定已在此期间停止。

把时间分成每块 100 步。在每块开始仍未停止的条件下，该块继续存活的概率不超过 1−p1001-p^{100}1−p100。反复使用条件概率即可得到几何衰减尾界；不必把各块的存活事件当作独立事件。

具体地，P(T>100k)≤(1−p100)k→0P(T>100k)\le(1-p^{100})^k\to0P(T>100k)≤(1−p100)k→0，故 P(T<∞)=1P(T<\infty)=1P(T<∞)=1。按百步分块对尾概率求和，ET≤100∑k≥0(1−p100)k=100/p100<∞ET\le100\sum_{k\ge0}(1-p^{100})^k=100/p^{100}<\inftyET≤100∑k≥0​(1−p100)k=100/p100<∞。

对整数停止时间，ET=Σ_{t≥0}P(T>t)。在第 k 个百步区间内，P(T>t)≤P(T>100k)，一块至多贡献100倍该概率，得到文中的上界。这个界可能很松：p=1 时实际只需当前位置 i 步，而界为100；它的用途是证明有限性。该论证事实上对任意 p>0 均适用。

同类问题

随机算法的终止可用相同分块方法：在任意未结束状态，都有固定概率在固定步数内完成，即可得到几何尾界。必须有统一下界，不能只知道每个状态的成功概率各自为正。

5. 圆环最后访问位置

题目

编号 0 至 100 的 101 个点围成一圈。游走从 0 出发，每步独立等概率走向左右邻点，起点视为已访问。求 50 是最后一个首次被访问的点的概率。

考点：环转区间；首次访问；边界命中。

查看分析与解答

必要知识

起点已经访问，所以最后访问点只能是其余100点。固定起点后，各点距离不同，不能直接说旋转对称使它们等可能。把目标点切成区间两端，可将最后访问条件改写为先到哪些边界。

分析思路

先要求访问目标两侧的邻点，再允许走到目标。按先访问左邻点还是右邻点分两类，各类用线性命中概率相乘。

解答步骤

切开后，到达两端0或N都意味着首次访问目标。要在此之前覆盖其余点，必须从1走到N−1或反向走；最近邻路径会自动经过中间全部点。因此只需追踪两个邻点，无须记录全部访问集合。

更一般地，N≥3N\ge3N≥3 点环中，从 0 出发，任意 j≠0j\ne0j=0 最后被访问的概率都是 1/(N−1)1/(N-1)1/(N−1)。这不能仅凭旋转对称性得出，因为起点已经固定。

在候选点 jjj 处把环切开，将其记为两端 0 和 NNN。其余点为 1,…,N−11,\ldots,N-11,…,N−1，出发位置变成某个 iii。要使候选最后访问，必须先到过 1 和 N−1N-1N−1，再碰端点。先到 1 的概率为 (N−1−i)/(N−2)(N-1-i)/(N-2)(N−1−i)/(N−2)。从 1 出发先到 N−1N-1N−1 而不碰 0 的概率为 1/(N−1)1/(N-1)1/(N−1)。先到右侧的对称贡献为 (i−1)/(N−2)⋅1/(N−1)(i-1)/(N-2)\cdot1/(N-1)(i−1)/(N−2)⋅1/(N−1)。

相加后起点 iii 消去，结果为 1/(N−1)1/(N-1)1/(N−1)。本题 N=101N=101N=101，答案为 1/1001/1001/100。

第一阶段从 i 出发先到1的概率为(N−1−i)/(N−2)，先到N−1的概率为(i−1)/(N−2)，两者和一。无论先到哪侧，跨越其余点而不先碰目标的成功率均为1/(N−1)。相乘相加后自然得到相同结果。101个点时为0.01，100个候选点概率之和恰为一。

同类问题

覆盖问题若图是一条路径或环，可利用连续访问区间减少状态。不能把本题结论直接推广到任意网络，结构改变后最后访问分布通常不均匀。

6. 顺序与随机访问内存

题目

对一个远大于处理器缓存的数组，每个元素读取一次。比较按地址顺序读取与按随机排列读取的性能，并解释可能的差异。

考点：缓存行；带宽与延迟；访存测量。

查看分析与解答

必要知识

CPU 缓存保存近期使用的数据，通常按缓存行而非单个变量搬运。空间局部性是相邻地址很快会被使用；预取则是在程序真正读取之前，提前请求预测到的数据。

分析思路

分别看一次搬运能用上多少数据、能否同时发出多次请求、地址转换是否命中。最后设计只改变访问顺序的比较实验。

解答步骤

假设缓存行64字节、元素8字节。顺序扫描时取回一行后可连续使用八个元素；大数组随机扫描时，这一行再次使用前可能已被淘汰。同样读取 n 个元素，底层实际搬运量因此可能相差很大。

缓存通常按一整行搬运数据。例如一行 64 字节、每个元素 8 字节，一次取回的内容包含 8 个相邻元素。顺序读时，这 8 个元素很快都会使用；随机读时，刚取回的一行可能只使用其中一个元素就转向别处。

顺序地址还容易被硬件预取器预测，并能形成多笔连续内存请求，使运行时间接近“总读取量÷有效带宽”。若随机访问存在指针依赖，后一次地址要等前一次读完才知道，性能更容易受单次访存延迟限制。跨大量内存页还会增加 TLB 未命中。

比较时应固定数组大小、元素类型、访问次数与结果使用方式，并预先生成随机下标，避免把随机数生成开销算入访存。若整个数组已在缓存中，两种方式的差距会缩小。

带宽描述每秒搬运多少字节，延迟描述一次请求等待多久。随机下标若已独立给出，处理器仍可能并行发出多次请求；链表式指针追踪则需等前一次返回才知道下个地址，较难隐藏延迟。实验应让读取结果参与校验，防止编译器删除无效工作，并区分首次访问和缓存预热后的情况。

同类问题

遇到两个同为 O(n) 的实现，进一步看数据布局、搬运量和依赖链。复杂度相同并不意味着硬件上的执行时间接近。

7. 超出物理内存

题目

一台物理内存为 16 GB 的计算机上，某程序申请并可能使用 24 GB 内存。分析申请时与实际访问时可能发生的情况，并说明应观测哪些指标。

考点：虚拟内存；工作集；换页诊断。

查看分析与解答

必要知识

虚拟地址是程序看到的地址范围；常驻集是目前真正放在物理内存中的页；工作集是近期反复需要的页。申请24GB不意味着24GB立即全部常驻，也不意味着只要分配成功就能高效使用。

鲨鱼说

申请内存像预留地址，真正反复使用的数据才决定工作集。相同的申请量，若访问方式不同，实际占用与换页开销可能相差很大。

分析思路

按申请、首次写入、反复访问三个阶段分析，分别检查地址空间、后备存储和当前可用物理页。再由监控指标定位是哪一阶段受限。

解答步骤

例如程序申请24GB但只操作其中2GB，其工作集仍可能放入16GB机器。若持续随机访问全部24GB，换出的页很快又需要读回，磁盘读写会成为主要开销。这两种程序具有相同申请量，却有完全不同的表现。

申请地址空间与实际占用物理页是两个阶段。操作系统可能先保留一段虚拟地址，直到程序写入某页时才分配后备存储；也可能在分配时就检查提交额度，直接返回失败。

若程序确实反复访问 24 GB，而可用物理内存小于工作集，系统可能把不活跃页写入交换区。随后又访问这些页时要从磁盘读回。频繁来回换页称为抖动，程序仍可能运行，但速度明显下降。若交换区、地址空间或提交额度不足，也可能分配失败或被系统终止。

诊断时分别看虚拟地址量、已提交内存、常驻集、缺页速率和磁盘活动。仅看到申请量超过物理内存，尚不能判断程序一定崩溃。减少同时驻留的数据、分块处理或使用外存算法，通常比反复申请更大的内存有效。

排查时先看申请是否返回失败，再看提交量与常驻量是否持续增长，最后结合缺页、换页读写和磁盘等待判断抖动。普通缺页也可能只是首次建立映射，应区分需要磁盘读取的缺页。分块算法的目标是让同时活跃的数据加上系统开销低于可用内存。

同类问题

估计内存需求要分清虚拟容量、峰值常驻量和活跃数据量。数据超过内存时，优先调整访问方式和算法，而不是只修改分配上限。

8. 排序一秒可行性

题目

对 10510^5105、10810^8108、101010^{10}1010 个 8 字节整数做比较排序。用快速排序的平均工作量与存储量估计“一秒完成”是否合理，并指出还需要哪些机器信息。

考点：数量级估算；比较排序；外存边界。

查看分析与解答

必要知识

O(n log n) 描述规模增长规律，不直接给出秒数。实际时间还取决于每次比较、交换和访问的代价。容量估算能先判断算法是否还能在内存中执行。

分析思路

先算数组字节数，再算比较量；给定一个明确的假设吞吐率作除法，并检查实际机器是否可能达到它。

解答步骤

log₂10⁵约16.61、log₂10⁸约26.58、log₂10¹⁰约33.22。与对应 n 相乘得到比较数量。8字节整数的原始存储为8n字节，另需考虑排序实现、输入缓冲和系统占用。

先分两笔账。运算账用 nlog⁡2nn\log_2nnlog2​n 估计比较数量，内存账用 8n8n8n 估计原数组字节数。即使机器平均每秒能完成 10910^9109 次这样的比较，三种规模仅比较部分也分别约需 0.0017、2.7、332 秒。这个吞吐只是用于演算的假设，未包含交换元素和访存。

数组放不进内存时，问题已变为外存排序，磁盘读写可能成为主要成本。实测应说明 CPU、线程数、可用内存、输入分布及是否包含数据读取；可先对较小规模计时，再检查扩规模时是否出现缓存或内存拐点。

三种规模的比较量约为 1.66×1061.66\times10^61.66×106、2.66×1092.66\times10^92.66×109、3.32×10113.32\times10^{11}3.32×1011，原数组分别占约 0.8 MB、0.8 GB、80 GB。第一种规模一秒完成可能合理，后两种须结合吞吐量和可用内存判断。快速排序的最坏时间还可能退化为 O(n2)O(n^2)O(n2)。

假设每秒10⁹次比较只是演算参数：若实际吞吐只有10⁸次，比较部分时间就全部乘十。80GB输入在16GB机器上还需分块排序及多路归并，磁盘至少要读取输入并写出结果，此时不能只按 CPU 比较速度外推。

同类问题

性能判断可按“容量是否放得下—运算量是多少—主要瓶颈是什么—小规模实测能否外推”展开。对固定范围整数还可讨论基数排序，但要明确已换了算法及额外存储条件。

9. 未缓存变量自增

题目

设普通整数变量 var 的最新值在内存中、尚未进入当前 CPU 的缓存，且编译器确实需要执行 ++var。解释一次自增的主要步骤，以及两个线程同时自增可能出现的问题。

考点：读改写；缓存一致性；语言内存模型。

查看分析与解答

必要知识

源代码的一条自增语句不一定是一条不可分割的机器操作。缓存一致性保证各核心对缓存副本的协调，原子性则保证整个读改写不被其他线程插入，两者解决的问题不同。

分析思路

先解释单线程的数据流，再画出两个线程交错执行的逻辑例子，最后指出语言规定和正确同步方式。

解答步骤

单线程需要先取得数据及修改权限，计算新值，再提交写入缓存。写缓冲与回写策略会推迟主存更新，因此不能把源代码语句完成等同于物理内存立即被写了一次。

处理器先取得包含 var 的缓存行，等待数据可用后完成加一，再把结果存入可写缓存行。写回主存的时机取决于缓存策略，不一定在该条语句结束时立即发生。多核共享该行时，还要取得修改权限并处理其他核心副本的一致性。

普通自增在逻辑上包含读、加、写三个动作。例如两线程都读到 7，各自计算 8，再各写入 8，最终只增加 1。这称为丢失更新。C++ 中无同步地并发读写同一普通对象还构成数据竞争，程序行为不能用这个示例作为唯一保证。

需要同步时可用语言提供的原子整数或互斥锁。volatile 不能代替线程同步。变量若能长期保存在寄存器内，单线程代码也可能被编译器合并或优化，具体机器指令需结合编译结果分析。

两线程读7再写8是理解丢失更新的示意；在 C++ 中，这种未同步冲突本身属于未定义行为，不能承诺最终值只会是8或9。原子 fetch_add 把读改写作为整体协调，互斥锁则可保护更大范围操作。多个独立变量若落在同一缓存行，还可能因争用该行产生伪共享。

同类问题

并发题先明确语言模型、共享对象和所需保证，再讨论硬件实现。volatile、缓存一致性、原子操作和锁不能互相替代。

10. 环境变量

题目

在 SSH 登录的 shell 中执行 export MODE=test 后，分别启动子程序、打开另一独立会话、退出后重新登录。哪些进程通常能读到这个值？怎样使以后登录时自动设置？

考点：进程继承；会话隔离；配置加载。

查看分析与解答

必要知识

每个进程有自己的环境变量集合。启动子进程时，父进程通常把当时的集合复制给它；这不是所有进程共享的一张可实时更新的表。export 的作用是让 shell 变量进入随后子进程可继承的环境。

分析思路

画出父子进程关系及创建时间。判断某个进程是否在 export 之后由该 shell 创建，再区分一次性的继承与登录时重新加载配置。

解答步骤

在当前 shell 设置 MODE=test 后运行 Python 子程序，它可通过进程环境读到 test。若先启动子程序再改变父 shell，已经运行的子程序环境不会自动更新。子程序改变自己的 MODE 也不会反向改父 shell。

环境变量是进程附带的一组字符串键值。export MODE=test 将变量加入当前 shell 的环境，随后由它创建的子程序通常继承该值；已经运行的其他进程以及父进程不会被追溯修改。

另一条独立 SSH 会话由登录服务创建，不是刚才 shell 的子进程，因此不会因为该次 export 自动获得变量。退出后重新登录也是新进程，临时设置一般消失。

若希望每次登录自动设置，应在实际使用的 shell 所读取的登录配置中加入赋值，或在服务管理器的环境配置中声明。验证时分别在父 shell、子程序和新会话中读取变量，就能区分“继承”与“重新执行配置”。

新 SSH 会话来自登录服务，是另一条进程分支。要让它获得变量，应让其启动流程读取相应配置；不同 shell 的登录、交互及非交互启动文件可能不同，应先确认实际使用方式。服务进程则应使用服务自身的环境配置，并在重新启动后验证。

同类问题

排查环境变量时同时检查设置在哪个进程、子进程何时创建、启动时读取哪个配置。只检查当前终端显示的值，不能证明服务或其他会话也有相同值。

11. 并行送餐与串行自取

题目

有 nnn 道菜，每道菜选择自取或配送。所有配送在时刻 0 同时开始，第 iii 道需非负时间 did_idi​。自取由一个人依次完成，第 iii 道耗时 pi≥0p_i\ge0pi​≥0，时间可相加且与顺序无关，两种方式同时进行。求全部到齐的最早时刻。

计算 p=[1,2,3,2,1]p=[1,2,3,2,1]p=[1,2,3,2,1]、d=[4,8,5,6,3]d=[4,8,5,6,3]d=[4,8,5,6,3] 的结果。

考点：最大完成时间；阈值判定；排序贪心。

查看分析与解答

必要知识

自取任务共享一个人，耗时相加；配送同时开始，耗时取最大。给定自取集合 S，总完成时间为 max(Σ_{i∈S}p_i,max_{i∉S}d_i)。因此不能逐道比较 p_i 和 d_i 后独立选择。

分析思路

反过来问能否在 T 内完成。配送超过 T 的菜被迫自取，其余配送不会超时，由此得到必要且充分的条件，再按配送时长降序枚举。

解答步骤

必要性：d_i>T 时只能自取，所以强制自取总时长不能超过 T。充分性：若该总和不超过 T，就依次自取这些菜，让剩余菜全部配送，两部分都在 T 内完成。证明充分性给出了实际安排，而不仅是一个下界。

若要求在 TTT 前到齐，则所有 di>Td_i>Tdi​>T 的菜都不能配送，只能自取；这些菜的自取时间总和必须不超过 TTT。其余菜配送即可，不必增加自取工作量。这给出可行性的充要条件。

因此按 did_idi​ 降序排列后，只需枚举“前 kkk 道自取、其余配送”。令前缀自取总时间为 PkP_kPk​，剩余配送最大时间为 dk+1d_{k+1}dk+1​，完成时刻为 max⁡(Pk,dk+1)\max(P_k,d_{k+1})max(Pk​,dk+1​)，再对 k=0,…,nk=0,\ldots,nk=0,…,n 取最小。

样例降序对应配送时间 8,6,5,4,38,6,5,4,38,6,5,4,3，自取时间 2,2,3,1,12,2,3,1,12,2,3,1,1。取前两道自取耗时 4，其余配送最长 5，因此 5 分钟到齐。若要求少于 5 分钟，配送时间 8、6、5 的三道都要自取，共需 7 分钟，故不可能更快。排序为 O(nlog⁡n)O(n\log n)O(nlogn)，枚举为 O(n)O(n)O(n)。

def finish_time(p, d):
    if len(p) != len(d):
        raise ValueError('长度不一致')
    jobs = sorted(zip(d, p), reverse=True)
    total = 0
    best = jobs[0][0] if jobs else 0
    for i, (_, pickup) in enumerate(jobs):
        total += pickup
        remaining = jobs[i+1][0] if i+1 < len(jobs) else 0
        best = min(best, max(total, remaining))
    return best

assert finish_time([1,2,3,2,1],[4,8,5,6,3]) == 5
assert finish_time([],[]) == 0

同类问题

目标是最小化“最晚完成时间”时，可先固定时限做可行性判断。若时限把任务分成必须处理与可选处理两类，常能得到排序、二分或贪心算法。
